## 总目标与完成定义

在 iStoreOS x86_64、aarch64 上提供持久磁盘中的多版本 Node/npm、Python/pip/venv、Go、Rust、Zig、Java 环境，以及按实例固定的私有 glibc/C++ 运行库。普通用户和应用使用同一固定 wrap 协议；各应用自行选择版本，不修改全局默认，不建立中央应用使用统计。OpenClaw 使用公共运行时完成安装、非 root Gateway 启动、sqlite-vec 实际向量查询、升级与失败回滚。

全部完成必须同时满足：九个里程碑通过；支持矩阵内各组合有实际验证；正式页面只呈现真实能力；真实 SDK 包构建、安装、升级及设备重启通过；遗留 mise/AgentFlow 和 OpenClaw 数据兼容通过；有可复现证据、恢复说明及候选包。源码检查、模拟测试、端口监听都不能替代目标设备上的业务验收。提交、推送、公开发布分别记录，不将公开发布作为本计划完成的隐含要求。

## 顺序、范围与共同规则

2026-11-24 最新执行方式：用户要求先直接同步源码、前端资源和必要二进制到两台测试机，不再逐轮构建 IPK/APK。M5–M8 先完成源码直部署的真实功能验收；包构建、包安装/升级、文件归属及依赖审计另标待人工确认，不能冒充已经完成。只有用户人工确认功能后，才进行人工 IPK/APK 编译。M4 已取得的实际包证据保留为历史基线。

依赖顺序：`M1 → M2 → M3`；M4、M5 均依赖 M3；M6、M7、M8 均依赖 M2/M3，产品接入还依赖 M4；M9 依赖 M1–M8。建议先按 M1、M2、M3、M4、M5 实施，再完成其他语言。M5 通过是第一个业务闭环，不代表全部计划完成。每个里程碑内按“实现 → 检查 → 故障修复 → 复验”工作。

- 测试目标沿用 x86_64 `root@192.168.30.7`、ARM64 `root@192.168.30.93`；先读取系统/架构/boot ID/磁盘/现有服务基线。设备重启或离线时记录事实，不把失联认定为安装通过，也不擅自替换目标。`.244` 不是本计划自动替代设备。
- SDK、工作目录、用户 HOME、包缓存和安装日志使用持久磁盘；存储脱挂时拒绝创建替代目录。不把 `/root`、overlay 或 tmpfs 作为隐式兜底。系统包仅保留小型程序、配置、清单和 Web 资产。
- 共享 SDK/运行库由管理器维护，普通用户不能改写；每个 UID/应用只写自己的目录。wrap 接受经过验证的 `ISTORE_RUNTIME_HOME`，路径、父目录权限与符号链接在后端检查；不对共享目录整体 chown。
- 不设置宿主全局 `LD_LIBRARY_PATH`，不修改系统 `/lib` 或 loader，不自动安装系统 C 工具链，不要求 Docker/apt，不替换已有 KSpeeder 服务。
- 不增加全局切换、应用列表、中央依赖登记或调用遥测；应用自己的 release 绑定和 Python venv 本地归属文件不属于中央登记。删除非默认环境必须明确固定入口将失效；禁止宣称“无人使用”或根据运行进程推断可安全删除。
- 原型版本、大小、npm 映射、glibc 布尔状态不能直接成为生产事实；真实目录、收据、能力探测与测量为准。没有通过验收的组合显示不可用并说明原因，不能靠隐藏失败项缩减已承诺范围。
- 统一保留退出码、日志和超时；取消后先收拢所属子进程，再清理本次候选；重启后中断任务可恢复，不自动重放包安装或恢复成假成功。
- 按用户最新执行指令，每个里程碑先输出任务树与验收标准，实现后自检；自检未通过最多优化三次，每次记录修改和复验。通过后自动进入下一里程碑，不逐项等待确认；三次优化仍失败或需要产品语义决策时暂停相关推进并报告。当前执行范围为先准备环境、再 M1–M8；M9 仍作为后续最终交付，不在本次自动执行范围。该规则取代初版总计三轮的限制，未通过时不得降低标准或误报完成。

## 支持矩阵与验证口径

| 工具 | x86_64 / aarch64 的目标范围 | 必须验证的实际能力 |
| --- | --- | --- |
| Node/npm | GNU 私有 glibc、宿主 musl；多版本与配套/兼容独立 npm | 固定版本、ABI、npm 生命周期、exec/fork、包前缀隔离；OpenClaw 特有要求留在 M5 |
| Python | GNU 私有 glibc、宿主 musl；多版本；配套 pip/venv | SSL/证书、SQLite、ctypes、原生扩展、离线 ensurepip、venv 装包和子进程 |
| Go | 标准工具链；多版本；UI 无 libc 选择 | go/gofmt、纯 Go 编译运行、固定工具链、持久目录；默认 CGO=0，显式 1 不被改写 |
| Rust | GNU 私有 glibc、宿主 musl；稳定版 minimal | rustc/cargo/宿主标准库、精确 triple、编译与有条件的链接运行、缓存及子进程 |
| Zig | 标准工具链；多版本；UI 无 libc 选择 | zig/env、最小构建运行、cc/c++、缓存；不自动接管 Go/Rust 链接器 |
| Java | Temurin 完整 JDK，21/25 LTS 各具体构建；仅私有 glibc | java/javac/jar、JVM/JNI、TLS、子进程、编译打包运行、持久属性 |

M1 必须形成精确版本 × 架构 × ABI × 构建/发行版 × npm/运行库修订的受控产物清单。六种语言在每种架构均至少有两个可共存的版本/构建用于验证多版本；对开放 GNU/musl 的语言，两种架构的两种 ABI 均须至少验证一个实际产物。不能假设所有版本覆盖所有组合：产物不存在的组合应在清单中明确不可用，并以实际可用版本满足相应 ABI 目标；如果某个承诺的架构/ABI 完全不可实现，里程碑保持未完成并报告，不自行取消该目标。

固定下载来源和 SHA256，保留供应方原有签名/证明及包管理器完整性检查。glibc 版本兼容与安全维护修订分别记录，不把旧 2.39 基线当作永远最新。单纯文件存在或 ELF 静态检查不足以证明可运行。
