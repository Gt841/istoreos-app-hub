# Runtime 仓库切换与依赖恢复

目标：切换当前仓库，完整保留旧仓库；应用保持固定版本，在当前仓库按需准备依赖；glibc 可检查和修复。不迁移业务数据，不扫描应用使用情况，不编译 IPK/APK。

任务树与可测试目标：

1. 仓库设置
   - 允许已安装环境时切换，旧文件不变；可切回、复用已有仓库。
   - 目标存储验证失败不改配置；安装/修复/清理锁存在时拒绝切换。
   - 显示确认、重启提示及实际 HOME；新 HOME 可能需要重新登录。
2. 公共依赖接口
   - ensure 固定目录项及库修订；复用相同任务，其他任务完成后再尝试。
   - 库缺失/损坏可后台修复；只用固定来源与摘要；引用中的库禁止普通清理。
   - 原库隔离保留到事务成功，失败/取消/中断有明确状态及恢复。
3. 应用接入
   - OpenClaw 在受监管的启动进程中准备依赖，验证后更新绑定，使用专用非 root UID 启动。
   - AgentFlow 后端不强制依赖 Node；已有代理启动时按原版本重新绑定当前仓库。
   - 原业务数据和代理包保留；依赖安装失败不静默回退旧仓库。
4. 验收
   - 本地语法、接口、前端类型与构建、事务失败/并发/恢复检查。
   - x86_64 .7：任务独占目录验证空仓库、切回、旧数据保留、库缺失与损坏恢复。
   - 实际 Node/npm、代理命令、Gateway 和 sqlite-vec 检查；正式配置测试后恢复。
   - 每轮记录失败和修复，最多三轮优化；不可把未执行检查计为通过。

版本沿用当前尚未发布候选（此前已经提升 release），不重复递增。ARM64、不配置模型密钥的端到端模型调用不属于本次验收。
